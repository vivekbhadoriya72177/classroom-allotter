Day 1 revision notes · Backend foundations · 27 October 2026
Project purpose: Help college class representatives find and coordinate rooms for rescheduled lectures, extra classes, and other activities. Eventually, availability will combine timetable data, CR activities, and recent empty-room reports without claiming uncertain information is guaranteed.

1. The mental model

A backend server waits for requests, runs the matching route logic, and sends a response. Our server uses Node.js to run JavaScript and Express to define API routes.

7. Creating a room with POST

express.json() parses an incoming JSON body and makes it available as request.body.

4. Normalize and check

↓
5. Store and respond

Validation rules

FieldRuleExample
codeRequired, non-empty string; normalized to uppercase"C-301"
buildingRequired, non-empty string"Academic Block C"
capacityRequired, positive whole-number JSON value80, not "80"
facilitiesOptional array of non-empty strings["projector"]

Why validate?

  • Clients can make mistakes or send hostile input.
  • Consistent data is easier to search and maintain.
  • Normalization prevents values such as c-301 and C-301 from becoming separate rooms.
  • Duplicate room codes return 409 Conflict.

8. HTTP status codes learned

StatusMeaningCurrent example
200 OKA retrieval succeeded.Get rooms or one existing room.
201 CreatedA new resource was created.Create a room successfully.
400 Bad RequestThe client supplied invalid input.Negative capacity or text ID.
404 Not FoundThe requested valid resource does not exist.Room ID 999.
409 ConflictThe request conflicts with existing data.Duplicate room code.
400 vs 404: /api/rooms/abc is invalid input, so it returns 400. /api/rooms/999 is a valid ID format but no such room exists, so it returns 404.

9. Manual practice

Read operations

curl http://localhost:3000/api/health
curl http://localhost:3000/api/rooms
curl "http://localhost:3000/api/rooms?minCapacity=50"
curl http://localhost:3000/api/rooms/2
curl -i http://localhost:3000/api/rooms/999

Create a room

curl -i -X POST http://localhost:3000/api/rooms \
  -H "Content-Type: application/json" \
  -d '{"code":"C-301","building":"Academic Block C","capacity":80,"facilities":["projector","whiteboard"]}'

Run the POST twice to observe 409 Conflict. Then restart the server and notice that the created room disappears.
